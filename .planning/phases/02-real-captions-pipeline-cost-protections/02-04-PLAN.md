## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client request → route.ts | IP extracted from x-forwarded-for; rate limit applied before any processing |
| route.ts → Redis | All Redis calls are server-side only; no client access to Redis |
| HTTP pre-flight response → client | 429/503 JSON bodies — no internal state exposed |
| SSE stream → client | All SSE events are Zod-typed before emission |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04-01 | Denial of Service | /api/extract without rate limit | mitigate | checkRateLimit is step 2 (before cache, before AI); limited=true returns HTTP 429 immediately |
| T-02-04-02 | Denial of Service | Global spend cap bypass | mitigate | checkSpendCap is step 3 (before cache, before AI); false returns HTTP 503 immediately |
| T-02-04-03 | Spoofing | IP spoofing via x-forwarded-for | accept | Vercel overwrites x-forwarded-for with true client IP (RESEARCH Pattern 2); cannot be spoofed at the client level |
| T-02-04-04 | Denial of Service | Cache stampede on cold cache | mitigate | acquireLock with Redis SET NX prevents N concurrent LLM calls for same videoId |
| T-02-04-05 | Information Disclosure | Error messages in HTTP 429/503 responses | mitigate | Error messages use generic copy ("Try again in a bit") without exposing Redis key names, IP addresses, or internal state |
