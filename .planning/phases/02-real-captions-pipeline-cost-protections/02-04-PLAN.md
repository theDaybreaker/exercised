<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client request → route.ts | IP extracted from x-forwarded-for; rate limit applied before any processing |
| route.ts → Redis | All Redis calls are server-side only; no client access to Redis |
| SSE stream → client | All events are Zod-typed before emission |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04-01 | Denial of Service | /api/extract without rate limit | mitigate | checkRateLimit is step 2 (before cache, before AI); limited=true terminates immediately |
| T-02-04-02 | Denial of Service | Global spend cap bypass | mitigate | checkSpendCap is step 3 (before cache, before AI); false terminates immediately |
| T-02-04-03 | Spoofing | IP spoofing via x-forwarded-for | accept | Vercel overwrites x-forwarded-for with true client IP (RESEARCH Pattern 2); cannot be spoofed at the client level |
| T-02-04-04 | Denial of Service | Cache stampede on cold cache | mitigate | acquireLock with Redis SET NX prevents N concurrent LLM calls for same videoId |
| T-02-04-05 | Information Disclosure | Error messages in SSE events | mitigate | Error messages use generic copy ("Try again in a bit") without exposing Redis key names, IP addresses, or internal state |
| T-02-04-SC | Tampering | npm/pip/cargo installs | accept | No new packages in this plan |
</threat_model>
