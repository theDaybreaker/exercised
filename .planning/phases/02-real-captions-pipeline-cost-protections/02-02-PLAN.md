<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process.env → Redis config | UPSTASH_REDIS_REST_URL and TOKEN are secrets; exposed only server-side |
| client IP → rate limiter | x-forwarded-for used for rate-limit identity (set by Vercel, not spoofable) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Elevation of Privilege | DAILY_EXTRACTION_CAP env var | accept | env var is server-side only; attacker cannot lower the cap without Vercel dashboard access |
| T-02-02-02 | Denial of Service | Upstash Redis instance | mitigate | Upstash free tier has request limits; if Redis is down, checkRateLimit should fail-open (let request through) to avoid blocking all traffic on Redis outage |
| T-02-02-03 | Tampering | Cache key structure | mitigate | extract:v1: prefix allows future cache invalidation by version; v1 prefix must not be omitted |
| T-02-02-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint (Task 0) for [ASSUMED] packages before install |
</threat_model>
